# Hermes Agent

Короткий русскоязычный гайд по установке, запуску и развёртыванию [Hermes Agent](https://github.com/NousResearch/hermes-agent) — open-source автономного AI-агента от Nous Research.

> **Статус:** первая практическая версия обзора. Команды и параметры могут меняться вместе с проектом Hermes Agent. [Развернутые ответы на вопросы, заданные по время презентации](docs\presentation-followup.md)

## Что такое Hermes Agent

Hermes — это не только чат с LLM, а агентная среда, которая может самостоятельно выполнять многошаговые задачи с помощью инструментов: запускать команды, изменять файлы, проводить веб-исследование, писать и отлаживать код, работать с документами и делегировать части задачи другим агентам.

Агент может работать:

- в терминале; 
- в Desktop GUI;
- через Gateway и мессенджеры (Telegram, Slack, почта, WeChat, WhatsApp и многие другие);
- на локальной машине, VPS или в контейнере;
- с моделями разных провайдеров, включая OpenAI-совместимые и локальные модели (LM Studio).

## Быстрый старт

### Установка

Для Linux, macOS или WSL2:

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

Затем запустите мастер настройки:

```bash
hermes setup
```

Мастер помогает выбрать провайдера, модель и необходимые интеграции. После настройки интерактивная сессия запускается командой:

```bash
hermes
```

Одноразовая задача:

```bash
hermes chat "Составь краткий план рефакторинга этого проекта"
```

Проверка состояния установки:

```bash
hermes doctor
```

Основные пользовательские данные находятся в `~/.hermes/`. Секреты хранятся в `.env`, настройки — в `config.yaml`.

## Развёртывание на VPS через Docker Compose

Для VPS удобен контейнерный запуск Gateway. Ниже — минимальная схема из практического гайда проекта.

Создайте рабочую директорию:

```bash
mkdir -p ~/hermes-agent/.hermes
cd ~/hermes-agent
```

Создайте `docker-compose.yml`:

```yaml
services:
  hermes:
    build:
      context: https://github.com/NousResearch/hermes-agent.git#main
    image: nousresearch/hermes-agent:latest
    container_name: hermes
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./.hermes:/opt/data
      - /var/run/docker.sock:/var/run/docker.sock
    environment:
      HERMES_UID: ${HERMES_UID:-10000}
      HERMES_GID: ${HERMES_GID:-10000}
    command: ["gateway", "run"]
```

Запустите контейнер и выполните первичную настройку:

```bash
HERMES_UID=$(id -u) HERMES_GID=$(id -g) docker compose up -d --build
docker compose exec hermes hermes setup
docker compose restart
```

Проверить состояние контейнера можно так:

```bash
docker compose ps
docker compose logs -f hermes
```

## Gateway и мессенджеры

Gateway — это шлюз между Hermes и внешними платформами. Он позволяет начать работу в терминале, а затем продолжить её, например, в Telegram или Discord, сохраняя контекст сессии.

Интерактивная настройка платформ:

```bash
hermes gateway setup
```

Запуск Gateway вручную:

```bash
hermes gateway run
```

В Docker Compose Gateway запускается автоматически командой `gateway run`.

В зависимости от платформы потребуются токены и параметры подключения. Например, для Telegram нужен токен бота, а для Slack — токен бота и токен приложения. Конкретные значения задаются через мастер настройки и переменные окружения, а не помещаются в публичный README или git-репозиторий.

Поддерживаемые сценарии включают Telegram, Discord, Slack, WhatsApp, Signal, электронную почту и другие платформы. Один Gateway может обслуживать несколько подключений.

## Что делает Hermes агентом

### Память между сессиями

Hermes сохраняет контекст работы и устойчивые факты о пользователе и окружении. Это позволяет не объяснять каждый раз одни и те же предпочтения, правила проекта и рабочий контекст.

### Skills и самоулучшение

Skills — это переиспользуемые инструкции для процедурных задач. После сложной работы полезный рабочий процесс можно сохранить как skill и применять в следующих сессиях. Таким образом, агент накапливает не только историю, но и способы решения повторяющихся задач.

### Goals и completion contract

`/goal` задаёт агенту цель и ожидаемый результат. Completion contract помогает явно описать, что считать завершением работы: какие файлы должны появиться, какие проверки пройти и какой результат вернуть пользователю. Это снижает риск ситуации, когда агент остановился после промежуточного шага.

### Delegate task

`delegate_task` запускает под-агентов с отдельным контекстом для независимых частей работы. Например, один агент может исследовать варианты решения, второй — проверить код, а основной агент затем соберёт результаты.

### Kanban и фоновые задачи

Для длинных задач Hermes позволяет раскладывать работу на отдельные этапы, отслеживать их состояние и выполнять независимые части в фоне. Это удобно для исследовательских задач, подготовки документов, ревью и других процессов, которые не обязательно выполнять одним непрерывным диалогом.

### Cron и постоянная автоматизация

Cron-задачи позволяют запускать работу по расписанию: собирать дайджесты, проверять источники, напоминать о задачах или отправлять результат в подключённый мессенджер.

### Profiles и MCP

Profiles изолируют конфигурацию, память, сессии и навыки разных рабочих контекстов. MCP позволяет подключать внешние серверы инструментов и расширять возможности агента без изменения его основного цикла.

## Безопасность

Hermes может выполнять команды и работать с файлами, поэтому его следует рассматривать как инструмент с доступом к окружению, а не как обычный чат.

Минимальные меры предосторожности:

- запускайте агент с минимально необходимыми правами;
- проверяйте команды, которые изменяют или удаляют данные;
- используйте Docker или другой изолированный backend для рискованных задач;
- не передавайте в контекст секреты без необходимости;
- ограничивайте доступ к Gateway через allowlist и pairing;
- не храните токены и `.env` в репозитории.

## Ограничения и disclaimer

Этот README — краткий практический обзор, а не официальная документация Hermes Agent. Набор команд, поддерживаемых платформ и конфигурационных параметров может измениться. Перед production-развёртыванием проверяйте актуальные инструкции проекта и тестируйте конфигурацию на отдельном окружении.

Практическое качество результата зависит от выбранной модели, провайдера, контекста задачи и доступных инструментов. Автономность агента не отменяет ревью действий, особенно при работе с VPS, секретами, базами данных и production-файлами.
